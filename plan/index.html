제작 계획

목적

공개 URL 하나로 평가자와 채용 담당자가 3분 안에 제가 무엇을, 왜, 어떻게 만들었는지 확인할 수 있는 포트폴리오 랜딩 페이지를 GitHub Pages에 만듭니다. 소개 대상은 직접 기획, 개발한 서비스 3개(TeraB, recordWEB, comax)입니다.

목표

영역측정 기준
콘텐츠서비스 3개를 개요, 목표, 사용 기술, 주요 기능, 코드, 역할, 결과의 7항목(총 21칸)으로 모두 작성, 그 밖의 프로젝트 6개 요약
배포전체 경로 직접 접속 정상, 깨진 링크와 콘솔 오류 0건
버전관리작업을 브랜치와 PR로 관리하고, 발견된 버그는 issue로 관리, Major.Minor.Patch 형식 버전 태그 사용
디자인 및 UX390, 820, 1440px에서 반응형 렌더링, 모든 페이지의 머리글과 간격 일관 유지
검색 정보전체 경로에 title, description, canonical, 이미지 alt 작성

템플릿 선정

자체 개발 테마를 선택했습니다. 포트폴리오용 랜딩 페이지이기 때문에 React, API 등의 기능이 필요 없다고 판단해 순수 HTML, CSS, JavaScript로 개발합니다. 구조는 홈 1개, 프로젝트 상세 3개, 계획 1개, 404 페이지입니다.

랜딩 구성은 rs-team.com(회사 소개 페이지)의 프로세스 단계와 실적 소개, coupin.io(랜딩 디자인 시스템 참고)의 문제에서 해결로 이어지는 흐름을 참고하되, 문구와 이미지는 직접 작성합니다.

선정 이유

  • 평가 대상이 서비스 소개이므로, 범용 블로그 테마보다 프로젝트를 앞세우는 랜딩 구조가 포트폴리오 목적에 더 맞습니다.
  • index.html, css, js 구조로 빌드 과정이 없어 main 브랜치 배포로 바로 운영할 수 있습니다.
  • GitHub Pages는 정적 호스팅이므로 서버 없이 동작하는 구성이 안정적입니다.
  • 직접 개발하므로 디자인과 페이지 구성을 사이트 전체에서 일관되게 유지할 수 있습니다.
